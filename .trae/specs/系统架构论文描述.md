# 系统架构描述（论文用）

## 3.X 系统总体架构

本系统采用 B/S（Browser/Server，浏览器/服务器）架构，基于前后端分离模式设计。系统总体架构如图 3-X 所示。

### 3.X.1 架构层次

系统自顶向下分为四个层次：

**（1）客户端层**

客户端层面向三类用户角色提供 Web 界面，分别为管理员端、宿管端和学生端。前端采用 Vue 3 框架结合 Element Plus 组件库开发，通过组件化设计实现页面复用，采用响应式布局适配不同分辨率的显示设备。

**（2）前端服务层**

前端服务层基于 Vite 开发服务器构建，运行于 5173 端口。通过配置代理服务器（端口 8080）将 HTTP 请求转发至后端服务，实现前后端通信。Vite 作为新一代前端构建工具，具有快速的冷启动和即时热更新特性，提升了开发效率。

**（3）后端服务层**

后端服务层基于 Spring Boot 2.7 框架开发，运行于 8080 端口，采用 MVC（Model-View-Controller）三层架构设计：

- **安全认证层**：基于 Spring Security 框架和 JWT（JSON Web Token）技术实现身份认证与权限校验。所有请求在进入控制器之前需通过 Token 验证，确保系统安全性。

- **控制器层（Controller）**：共包含 20 个控制器，负责接收 HTTP 请求、参数校验、调用业务逻辑层并返回响应结果。每个控制器对应一个业务模块，如 StudentController 负责学生管理相关接口。

- **业务逻辑层（Service）**：与控制器层一一对应，负责处理核心业务逻辑、事务控制、数据校验等。例如在添加学生时，Service 层负责密码加密（BCrypt）、数据关联等操作。

- **数据访问层（Mapper）**：基于 MyBatis-Plus 框架实现，与实体类（Entity）一一对应，负责执行 SQL 语句，完成对数据库的增删改查（CRUD）操作。

**（4）数据存储层**

数据存储层采用 MySQL 8.0 关系型数据库，运行于 3307 端口，数据库名为 dormitory_system。数据库共包含 26 张表，涵盖用户表（管理员、宿管、学生）、资源表（楼栋、宿舍、床位）、业务表（考勤、报修、失物招领、水电费等）以及系统表（日志、通知、规则等）。

### 3.X.2 数据流向

系统的数据流向遵循自上而下的调用模式：

1. 用户在浏览器发起操作请求（如添加学生）
2. 前端通过 HTTP 协议将请求发送至 Vite 开发服务器
3. Vite 通过代理将请求转发至后端 8080 端口
4. 后端安全认证层验证 JWT Token 的有效性
5. 请求进入对应的 Controller 层，进行参数校验
6. Controller 调用 Service 层处理业务逻辑
7. Service 层调用 Mapper 层执行数据库操作
8. Mapper 层通过 JDBC 连接数据库，执行 SQL 语句
9. 查询结果沿原路返回，最终以 JSON 格式响应给前端
10. 前端接收响应数据并更新页面展示

系统采用当前主流的技术栈，具体如表 3-X 所示。

### 3.X.4 架构特点

本系统架构具有以下特点：

**（1）前后端分离**

前端专注于页面展示和用户交互，后端专注于业务逻辑和数据处理。前后端通过 RESTful API 进行通信，降低了系统耦合度，便于独立开发和维护。

**（2）分层解耦**

采用经典的三层架构（Controller-Service-Mapper），各层职责明确，层与层之间通过接口调用，便于代码复用和单元测试。

**（3）安全性高**

基于 Spring Security 和 JWT 实现双重安全机制，所有接口需通过 Token 验证，支持基于角色的权限控制（RBAC），确保不同角色用户只能访问授权资源。

**（4）可扩展性强**

模块化设计使得系统具有良好的可扩展性。新增功能模块时，只需在对应层次添加新的 Controller、Service 和 Mapper，不影响现有功能。

**（5）性能优化**

采用连接池技术（HikariCP）管理数据库连接，减少连接创建和销毁的开销；使用 BCrypt 加密算法存储密码，虽然增加了计算开销，但提升了安全性；前端通过 Vite 实现快速构建和按需加载，优化了页面加载速度。
