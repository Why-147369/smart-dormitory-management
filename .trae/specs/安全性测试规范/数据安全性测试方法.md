# 数据安全性测试方法

## 测试目的

模拟数据传输过程中的拦截、篡改等攻击行为，验证系统的数据加密与防护机制。

## 测试环境配置

- **JMeter 版本**: 5.6.3
- **测试目标**: 宿舍管理系统 API
- **服务器地址**: http://localhost:8080

---

## 一、密码传输安全性测试

### 测试场景
验证用户登录时密码是否加密传输，防止明文密码被拦截窃取。

### 测试步骤

#### 1. 正常登录（基线测试）

**配置 HTTP 请求：**
- 方法：POST
- 路径：/api/auth/login
- Content-Type: application/json
- 消息体数据：
```json
{
  "username": "admin",
  "password": "admin123"
}
```

**预期结果：**
- ✅ 登录成功，返回 Token
- ⚠️ **问题**: 密码以明文传输，存在安全风险

#### 2. 拦截密码数据（Wireshark 抓包）

**步骤：**
1. 启动 Wireshark，选择网卡
2. 设置过滤条件：http.request.method == "POST"
3. 执行 JMeter 登录请求
4. 捕获数据包，查看密码字段

**预期结果：**
- ❌ **高风险**: 密码 admin123 明文可见
- ✅ **安全**: 密码已加密，显示为密文

## 二、JWT Token 篡改测试

### 测试场景
验证系统是否能检测到被篡改的 Token，防止伪造身份。

### 测试步骤

#### 1. 获取合法 Token

**配置 HTTP 请求：**
- 方法：POST
- 路径：/api/auth/login
- 消息体：
```json
{
  "username": "admin",
  "password": "admin123"
}
```

**添加 JSON Extractor：**
- 变量名：token
- JSON 路径：$.data.token

#### 2. 篡改 Token 测试

**方案 A：修改 Token 签名**

**配置 HTTP 请求：**
- 方法：GET
- 路径：/api/admin/user/list
- HTTP 请求头:
  - Authorization: Bearer ${token}tampered
  - Content-Type: application/json

**预期结果：**
- ✅ **安全**: 返回 401/403，Token 验证失败
- ❌ **风险**: 返回 200，Token 被接受

**方案 B：使用过期 Token**

**步骤：**
1. 登录获取 Token
2. 等待 Token 过期（通常 24 小时）
3. 使用过期 Token 访问受保护接口

**预期结果：**
- ✅ **安全**: 返回 401，提示 Token 过期
- ❌ **风险**: 返回 200，过期 Token 仍有效

**方案 C：伪造 Token**

**配置 HTTP 请求：**
- 方法：GET
- 路径：/api/admin/user/list
- HTTP 请求头:
  - Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.faked.signature

**预期结果：**
- ✅ **安全**: 返回 401/403
- ❌ **风险**: 返回 200

## 三、敏感数据保护测试

### 测试场景
验证系统返回的敏感数据（密码、手机号等）是否脱敏或加密。

### 测试步骤

#### 1. 查询学生列表

**配置 HTTP 请求：**
- 方法：GET
- 路径：/api/admin/student/list?page=1&size=10
- HTTP 请求头:
  - Authorization: Bearer ${token}
  - Content-Type: application/json

**检查响应数据：**
```json
{
  "data": {
    "records": [
      {
        "id": 1,
        "name": "张三",
        "phone": "138****1234",
        "password": "***",
        "idCard": "310***1234"
      }
    ]
  }
}
```

**预期结果：**
- ✅ **安全**: 敏感字段脱敏显示
- ❌ **风险**: 明文显示手机号、身份证、密码

#### 2. 查询用户详情

**配置 HTTP 请求：**
- 方法：GET
- 路径：/api/admin/user/1
- HTTP 请求头:
  - Authorization: Bearer ${token}

**检查响应数据：**
- 密码字段不应返回
- 或密码字段应为加密/脱敏格式

## 四、请求参数篡改测试

### 测试场景
验证系统是否能检测并阻止恶意篡改的请求参数。

### 测试步骤

#### 1. 篡改用户 ID（水平越权）

**步骤：**
1. 学生 A 登录（ID=1），获取 Token
2. 查询学生 A 的信息：/api/student/info/1
3. 篡改 ID 为学生 B：/api/student/info/2

**配置 HTTP 请求：**
- 方法：GET
- 路径：/api/student/info/2
- HTTP 请求头:
  - Authorization: Bearer ${student_token}

**预期结果：**
- ✅ **安全**: 返回 403，禁止访问他人数据
- ❌ **风险**: 返回 200，成功获取他人数据

#### 2. 篡改角色 ID（垂直越权）

**步骤：**
1. 普通用户登录，获取 Token
2. 尝试访问管理员接口

**配置 HTTP 请求：**
- 方法：GET
- 路径：/api/admin/user/list
- HTTP 请求头:
  - Authorization: Bearer ${user_token}
  - X-Role-Id: 2

**预期结果：**
- ✅ **安全**: 返回 403，角色权限不足
- ❌ **风险**: 返回 200，越权成功

#### 3. 篡改审批状态

**配置 HTTP 请求：**
- 方法：PUT
- 路径：/api/checkin/apply/approve/1
- HTTP 请求头:
  - Authorization: Bearer ${student_token}
  - Content-Type: application/json
- 消息体数据：
```json
{
  "status": "approved"
}
```

**预期结果：**
- ✅ **安全**: 返回 403，学生无权审批
- ❌ **风险**: 返回 200，审批成功

## 五、重放攻击防护测试（可选）

### 测试场景
验证系统是否能检测并阻止重放攻击。

### 测试步骤

#### 1. 重放登录请求

**步骤：**
1. 捕获正常登录请求
2. 复制该请求，发送 5 次
3. 观察服务器响应

**配置 HTTP 请求：**
- 方法：POST
- 路径：/api/auth/login
- 消息体：
```json
{
  "username": "admin",
  "password": "admin123"
}
```

**预期结果：**
- ✅ **安全**: 多次请求后限制频率或要求验证码
- ❌ **风险**: 所有请求都成功，无防护

#### 2. 重放 Token 请求

**步骤：**
1. 使用 Token A 访问接口
2. 立即再次使用 Token A 访问同一接口

**预期结果：**
- ✅ **安全**: Token 只能使用一次（nonce 机制）
- ❌ **风险**: Token 可重复使用（正常情况）

## 七、安全建议

### 1. 密码传输加密

**问题**: 当前密码以明文传输

**建议方案**：
- 前端使用 RSA 公钥加密密码
- 后端使用私钥解密
- 或使用 HTTPS 加密传输层

**示例代码（前端）**：
```javascript
// 使用 JSEncrypt 库
const encrypt = new JSEncrypt();
encrypt.setPublicKey(rsaPublicKey);
const encryptedPassword = encrypt.encrypt(password);
```

### 2. Token 安全增强

**建议**：
- 设置合理的 Token 过期时间（建议 2-4 小时）
- 实现 Token 刷新机制（Refresh Token）
- 添加 Token 黑名单（登出时加入）

### 3. 敏感数据脱敏

**建议**：
- 手机号：138****1234
- 身份证：310***********1234
- 密码：不返回或返回***

**示例代码（后端）**：
```java
@JsonSerialize(using = PhoneDesensitizeSerializer.class)
private String phone;
```

### 4. 权限校验强化

**建议**：
- 所有接口都必须校验权限
- 不仅校验登录状态，还要校验角色权限
- 关键操作添加二次验证

### 5. 重放攻击防护

**建议**：
- 添加请求时间戳校验（5 分钟内有效）
- 添加随机数（nonce）机制
- 关键接口添加图形验证码

## 十、常见问题

### Q1: 为什么 Token 篡改测试返回 401？

**A**: 说明系统 Token 验证机制正常工作，能检测到非法 Token。

### Q2: 如何测试 HTTPS 加密传输？

**A**: 
1. 配置服务器启用 HTTPS
2. JMeter 使用 https:// 协议
3. 使用 Wireshark 抓包，验证数据是否加密

### Q3: 重放攻击测试有必要吗？

**A**: 对于高安全系统（金融、政务）很有必要，一般管理系统可选。
