# 提交数据并发性能测试方法

## 1. 测试目的

验证系统在多用户同时提交学生信息场景下的性能表现和稳定性。

---

## 2. 测试接口

| 接口名称 | 请求路径         | 请求方式 |
| ---- | ------------ | ---- |
| 添加学生 | /api/student | POST |

---

## 3. 测试数据规格

| 字段 | 后端字段          | 格式               | 示例                                  |
| -- | ------------- | ---------------- | ----------------------------------- |
| 学号 | studentNumber | 2020 开头 + 10 位随机数字 | 20201234567890                      |
| 姓名 | name          | 随机姓名             | 学生${__Random(1,1000)}             |
| 性别 | gender        | **数字：0=女，1=男**   | 0 或 1                               |
| 电话 | phone         | 11 位数字            | 138${__Random(10000000,99999999)} |
| 学院 | college       | 固定值              | 自然科学学院                              |
| 专业 | major         | 固定值              | 环艺工程                                |
| 班级 | className     | 固定值              | 10 班                                 |
| 密码 | password      | 固定值              | 123456                              |

---

## 4. JMeter 详细配置

### 4.1 线程组配置

1. 右键点击"测试计划" → 添加 → 线程（用户） → 线程组
2. 配置参数：
   - 线程数：`1000`
   - Ramp-Up 时间：`15秒`
   - 循环次数：`1`
   - 调度器：不勾选

### 4.2 添加 Cookie 管理器

1. 右键点击线程组 → 添加 → 配置元件 → HTTP Cookie 管理器
2. **无需额外配置**，保持默认即可
3. Cookie 管理器会自动保存登录返回的 Cookie，后续请求自动携带

### 4.3 登录获取 Token

> 为了避免1000个线程都执行登录操作，使用"仅一次控制器"让登录只执行1次

#### 4.3.1 创建仅一次控制器

1. 右键点击线程组 → 添加 → 逻辑控制器 → 仅一次控制器
2. 后续的登录请求放在这个控制器下面

#### 4.3.2 创建 HTTP 请求

1. 右键点击"仅一次控制器" → 添加 → 采样器 → HTTP 请求
2. 配置如下：
   - 名称：`管理员登录`
   - 服务器名称或 IP：`localhost`（根据实际部署修改）
   - 端口号：`8080`（根据实际部署修改）
   - 协议：`http`
   - 请求方法：`POST`
   - 路径：`/api/auth/login`
   - 内容编码：`UTF-8`

#### 4.3.3 配置请求头

1. 右键点击"管理员登录"HTTP 请求 → 添加 → 配置元件 → HTTP 信息头管理器
2. 添加以下请求头：
   - 名称：`Content-Type`，值：`application/json`

#### 4.3.4 配置请求体

1. 右键点击"管理员登录"HTTP 请求 → 添加 → 配置元件 → HTTP 请求体
2. 输入以下 JSON：
```json
{
  "username": "admin",
  "password": "admin123",
  "userType": 3
}
```
**注意**：
- userType 参数必须填写：1=学生，2=宿管，3=管理员
- 密码请替换为实际的管理员密码

#### 4.3.5 提取 Token

1. 右键点击"管理员登录"HTTP 请求 → 添加 → 后置处理器 → JSON 提取器
2. 配置如下：
   - 名称：`提取 Token`
   - 应用范围：当前采样器
   - 变量名称：`token`
   - JSON 路径表达式：`$.data.token`
   - 匹配数字：`1`
   - 默认值：`token_not_found`

#### 4.3.6 验证 Token 提取

1. 右键点击线程组 → 添加 → 监听器 → 查看结果树
2. 运行测试，检查 Token 是否成功提取

### 4.4 学生信息提交

#### 4.4.1 创建 HTTP 请求

1. 右键点击线程组 → 添加 → 采样器 → HTTP 请求
2. 配置如下：
   - 名称：`添加学生`
   - 服务器名称或 IP：`localhost`
   - 端口号：`8080`
   - 协议：`http`
   - 请求方法：`POST`
   - 路径：`/api/student`
   - 内容编码：`UTF-8`

#### 4.4.2 配置请求头

1. 右键点击"添加学生"HTTP 请求 → 添加 → 配置元件 → HTTP 信息头管理器
2. 添加以下请求头：
   - 名称：`Content-Type`，值：`application/json`
   - 名称：`Authorization`，值：`Bearer ${token}`

#### 4.4.3 配置请求体

1. 右键点击"添加学生"HTTP 请求 → 添加 → 配置元件 → HTTP 请求体
2. 输入以下 JSON：
```json
{
  "studentNumber": "2020${__Random(1000000000,9999999999)}",
  "name": "学生${__Random(1,1000)}",
  "gender": ${__RandomFromMultipleChoice(0,1)},
  "phone": "138${__Random(10000000,99999999)}",
  "college": "自然科学学院",
  "major": "环艺工程",
  "className": "10班",
  "password": "123456"
}
```

**注意**：gender 必须传数字，不能传"男/女"！
- 0 = 女
- 1 = 男

### 4.5 添加监听器

#### 4.5.1 聚合报告

1. 右键点击线程组 → 添加 → 监听器 → 聚合报告
2. 用于查看总体性能指标

#### 4.5.2 查看结果树

1. 右键点击线程组 → 添加 → 监听器 → 查看结果树
2. 用于查看每个请求的详细信息和错误信息

#### 4.5.3 响应时间图

1. 右键点击线程组 → 添加 → 监听器 → 响应时间图
2. 用于直观查看响应时间分布

#### 4.5.4 用表格查看结果

1. 右键点击线程组 → 添加 → 监听器 → 用表格查看结果
2. 用于导出测试结果数据

### 4.6 测试计划结构

完整的测试计划结构应该如下：

```
测试计划
└── 线程组
    ├── HTTP Cookie 管理器（自动管理登录Cookie）
    ├── 仅一次控制器（确保登录只执行1次）
    │   └── 管理员登录
    │       ├── HTTP 信息头管理器
    │       ├── HTTP 请求体
    │       └── JSON 提取器（提取 token）
    ├── 添加学生
    │   ├── HTTP 信息头管理器
    │   └── HTTP 请求体
    ├── 聚合报告
    ├── 查看结果树
    ├── 响应时间图
    └── 用表格查看结果
```

**重要说明**：
- HTTP Cookie 管理器放在线程组下面（全局生效）
- 管理员登录放在"仅一次控制器"下面（只执行1次）
- 添加学生放在线程组下面（1000个线程都会执行）

## 7. 测试数据清理

测试完成后，可使用以下 SQL 批量删除测试数据：

```sql
-- 删除学号以 2020 开头的测试数据
DELETE FROM student WHERE student_number LIKE '2020%';

-- 或删除指定日期范围的数据
DELETE FROM student WHERE create_time BETWEEN '2024-01-01' AND '2024-12-31';
```

## 8. 注意事项

1. **接口路径**：是 `/api/student`，不是 `/api/student/add`
2. **gender 字段**：必须是数字 0 或 1，不能是"男/女"
3. **学号唯一**：使用 CSV 或分批测试避免学号冲突
4. **数据清理**：测试完成后执行 DELETE 语句清理测试数据
5. **Token 有效期**：如果测试时间较长，Token 可能过期，需要在后续请求中重新获取
6. **服务器地址**：根据实际部署情况修改服务器 IP 和端口
7. **管理员账号**：使用真实有效的管理员账号密码
