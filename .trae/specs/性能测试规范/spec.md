# 性能测试规范 Spec

## Why
智能宿舍管理系统需要满足500人同时在线使用的性能要求，因此需要进行性能测试以验证系统在高并发场景下的稳定性和响应速度，确保系统能够满足实际使用需求。

## What Changes
- 制定性能测试计划，明确测试目标、范围和方法
- 设计性能测试用例，覆盖登录、查询、数据提交等核心功能
- 确定性能测试工具和环境
- 定义性能指标基准

## Impact
- Affected specs: 系统测试章节
- Affected code: 无（测试文档）

---

## 性能测试计划

### 1. 测试目标
- 验证系统在500人并发访问下的响应时间是否在合理范围内
- 确定系统的最大并发承载能力
- 识别系统性能瓶颈并提供优化建议

### 2. 测试范围
- **核心功能测试**：
  - 用户登录/登出
  - 数据查询（学生信息、宿舍信息、报修记录等）
  - 数据提交（报修申请、打卡、换寝申请等）
  - 数据导出（Excel导出）

### 3. 测试方法
- **负载测试**：模拟500用户同时使用系统，测试正常负载下的性能表现
- **压力测试**：逐步增加并发用户数，直至系统达到极限，记录最大承载能力

## 性能测试用例

### 用例1：500用户并发登录测试

| 项目 | 内容 |
|------|------|
| 测试场景 | 模拟500名学生同时登录系统 |
| 测试步骤 | 1. 准备500个测试账号<br>2. 使用性能测试工具模拟并发登录请求<br>3. 记录登录响应时间 |
| 预期结果 | 登录成功率≥99%，平均响应时间≤3秒 |
| 判定标准 | 通过/不通过 |

### 用例2：500用户并发查询测试

| 项目 | 内容 |
|------|------|
| 测试场景 | 模拟500名用户同时进行数据查询 |
| 测试步骤 | 1. 准备测试数据<br>2. 模拟并发查询请求（学生列表、宿舍列表等）<br>3. 记录查询响应时间 |
| 预期结果 | 平均响应时间≤2秒 |
| 判定标准 | 通过/不通过 |

### 用例3：200用户并发提交数据测试

| 项目 | 内容 |
|------|------|
| 测试场景 | 模拟200名用户同时提交报修申请 |
| 测试步骤 | 1. 准备测试账号和表单数据<br>2. 模拟并发提交请求<br>3. 记录提交成功率和响应时间 |
| 预期结果 | 提交成功率≥99%，平均响应时间≤3秒 |
| 判定标准 | 通过/不通过 |

### 用例4：系统压力测试

| 项目 | 内容 |
|------|------|
| 测试场景 | 逐步增加并发用户数，测试系统极限 |
| 测试步骤 | 1. 从100用户开始，每分钟增加100用户<br>2. 持续增加直至系统出现明显性能下降或错误<br>3. 记录各阶段的响应时间和错误率 |
| 预期结果 | 确定系统最大并发承载量 |
| 判定标准 | 记录最大承载量 |

## 性能指标基准

| 指标 | 目标值 | 警告值 | 严重值 |
|------|--------|--------|--------|
| 平均响应时间 | ≤3秒 | 3-5秒 | >5秒 |
| 并发用户数 | 500 | - | - |
| 成功率 | ≥99% | 95%-99% | <95% |
| CPU使用率 | ≤70% | 70%-85% | >85% |
| 内存使用率 | ≤80% | 80%-90% | >90% |

---

## 测试工具

- **负载测试工具**：JMeter 或 Apache Bench (ab)
- **监控工具**：JConsole、Visual VM、Windows任务管理器
- **数据库监控**：MySQL慢查询日志

---

## 测试环境

- **服务器配置**：与生产环境一致
- **数据库**：包含足够的测试数据（建议1000条以上学生记录）
- **网络**：局域网环境，减少网络延迟影响
