# 安全性测试方法指南

## 概述
本文档详细介绍智能宿舍管理系统的安全性测试方法，包括密码安全测试、权限测试、JWT令牌测试和数据安全测试。

---

## 一、密码安全性测试

### 1.1 测试目的
验证系统密码是否以安全方式存储，防止密码泄露。

### 1.2 测试工具
- Navicat 或 MySQL Workbench（数据库管理工具）
- IDEA 或 VS Code（代码查看）

### 1.3 测试步骤

#### 步骤1：检查数据库密码存储

打开 MySQL 数据库管理工具，连接数据库后执行以下 SQL：

`sql
-- 查看学生表的密码字段
SELECT id, student_number, password FROM student LIMIT 5;

-- 查看管理员表的密码字段
SELECT id, username, password FROM admin LIMIT 5;

-- 查看宿管员表的密码字段
SELECT id, username, password FROM dormitory_manager LIMIT 5;
`

#### 步骤2：验证密码是否加密

检查查询结果中的 password 字段：
- 正确：密码应该是加密字符串，格式类似 $... 或 $...
- 错误：密码是明文（如 123456）

#### 步骤3：检查密码加密实现代码

1. 打开项目中的 AuthServiceImpl.java 文件
2. 查找 PasswordEncoder 或 BCrypt 关键字

预期结果：应使用 Spring Security 的 BCryptPasswordEncoder。

### 1.4 预期结果
- 密码以 BCrypt 加密形式存储
- 密码字段不可逆加密
- 使用 Spring Security 标准加密算法

## 二、权限测试

### 2.1 测试目的
验证系统基于角色的访问控制（RBAC）是否正确实现，不同角色用户只能访问其权限范围内的功能。

### 2.2 测试工具
- Postman（推荐）
- JMeter

### 2.3 测试步骤

#### 步骤1：准备测试账号

| 角色 | userType | 说明 |
|------|----------|------|
| 学生 | 1 | 普通学生账号 |
| 宿管员 | 2 | 管理特定楼栋的宿管员 |
| 管理员 | 3 | 系统管理员 |

#### 步骤2：测试未授权访问

使用 Postman 发送请求（不携带 Token）：

`
请求方式：GET
请求地址：http://localhost:8080/api/student/list
Headers：无
`

预期结果：返回 401 Unauthorized 或 403 Forbidden

#### 步骤3：测试学生权限

1. 使用学生账号登录，获取 Token
`json
POST /api/auth/login
{
    \"username\": \"学号\",
    \"password\": \"123456\",
    \"userType\": 1
}
`

2. 使用学生 Token 尝试访问受保护接口

预期结果：访问非学生接口返回 403 Forbidden

#### 步骤4：测试宿管员权限

1. 使用宿管员账号登录，获取 Token
2. 使用宿管员 Token 访问学生列表

预期结果：只能看到所管理楼栋的学生

#### 步骤5：测试管理员权限

1. 使用管理员账号登录，获取 Token
2. 使用管理员 Token 访问所有接口

预期结果：可以访问所有功能和数据

## 三、JWT 令牌安全测试

### 3.1 测试目的
验证 JWT 令牌的安全性，包括有效性验证、过期处理和防篡改机制。

### 3.2 测试工具
- Postman
- JWT 在线解码工具（jwt.io）

### 3.3 测试步骤

#### 步骤1：测试有效令牌

1. 使用账号登录获取 Token
2. 使用 Token 访问受保护接口

`
GET /api/student/list
Headers:
  Authorization: Bearer <token>
`

预期结果：正常返回数据

#### 步骤2：解码 JWT 令牌

1. 复制登录返回的 Token
2. 访问 https://jwt.io 解码
3. 检查 Token 内容

预期结果：包含 userId、userType、exp（过期时间）

#### 步骤3：测试令牌过期

1. 等待 Token 过期（或使用过期 Token 测试）
2. 使用过期 Token 访问接口

预期结果：返回 Token 已过期错误

#### 步骤4：测试令牌篡改

1. 获取正常 Token
2. 篡改 Token 任意字符
3. 使用篡改后的 Token 访问接口

预期结果：返回签名验证失败错误

## 四、数据安全性测试

### 4.1 测试目的
验证系统对敏感数据的保护措施。

### 4.2 测试步骤

#### 步骤1：检查敏感数据返回

1. 使用账号登录
2. 调用获取用户信息的接口
3. 检查响应 JSON 数据

预期结果：响应中不包含 password 和 token 字段

#### 步骤2：检查数据库连接配置

查看 application.yml 文件中的数据库配置。
