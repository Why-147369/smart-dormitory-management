## 一、登录认证

**流程**：用户输入账号密码 + 选择角色类型 → 后端查对应表验证 → BCrypt 比对密码 → 生成 JWT Token → 返回给前端 → 前端存 sessionStorage

**验证逻辑**：
1. 根据 `userType` 判断查哪张表（1=student，2=dormitory_manager，3=admin）
2. 查出用户记录，取到 BCrypt 密文
3. `passwordEncoder.matches(明文, 密文)` 比对
4. 匹配 → `JwtUtil.generateToken(userId, userType, username)` 生成 Token
5. 记录登录日志到 `login_log` 表

**涉及的表**：`student` / `dormitory_manager` / `admin`、`login_log`

**代码**：`AuthServiceImpl.java`（验证）、`JwtUtil.java`（生成Token）、`JwtAuthenticationFilter.java`（拦截验证）

## 二、学生端功能

### 2.1 在线报修

**状态流转**：0-待处理 → 1-已接单 → 2-维修中 → 3-已完成

**流程**：
1. 学生选报修类型、填描述、上传图片（最多4张）
2. 提交 → 系统自动生成报修单号（BX+时间戳），status=0
3. 宿管查看本楼栋报修列表，紧急工单（is_emergency=1）置顶标红
4. 宿管接单 → status=1，宿管可转派给维修师傅
5. 开始维修 → status=2
6. 维修完成 → status=3，自动通知学生评价
7. 学生评价（满意/一般/不满意）→ `repair_comment` 表
8. 宿管未接单前学生可取消 → status=4

**涉及的表**：`repair`、`repair_type`、`repair_comment`、`message`、`student`

**代码**：`RepairController.java`（核心）、`RepairCommentController.java`（评价）、`Constant.java`（状态常量定义）

---

### 2.2 换寝申请

**状态**：0-待审批 → 1-已通过 / 2-已驳回 / 3-已取消

**流程**：
1. 学生选择本楼栋内空闲宿舍和床位，填换寝原因 → 提交
2. 系统校验目标床位是否空闲（status=0）
3. 宿管审批 → 通过则执行多表联动更新（核心业务逻辑）：

```
① 释放原床位（bed.status=0，studentId=null）
② 原宿舍人数 -1（room.currentCount）
③ 占用新床位（bed.status=1，bed.studentId=学生ID）
④ 新宿舍人数 +1
⑤ 更新 student 表（buildingId、roomId、bedNumber）
⑥ 申请状态 → 已通过，记录审批人和时间
```

4. 审批拒绝 → 记录驳回原因
5. 所有操作在同一方法内完成，数据库事务保证原子性

**涉及的表**：`student`、`bed`、`room`、`room_change`

**代码**：`RoomChangeController.java`，审批方法在第 1558 行附近（论文附录）

### 2.3 智能客服（创新功能）

**两种模式**：
| chatType | 模式 | 说明 |
|----------|------|------|
| 1 | 智能客服 | 调 DeepSeek API 自动回复 |
| 2 | 人工客服 | 转管理员人工回复 |

**流程**：
1. 学生创建会话（指定 chatType）
2. 发送消息 → 写入 `chat_message` 表（sender_type=1）
3. 如果是智能客服模式 → 后端调用 `https://api.deepseek.com/v1/chat/completions`
4. API 返回 → AI 回复写入 `chat_message`（sender_type=2）
5. 如果是人工客服 → 管理员在后台回复（sender_type=3）
6. 支持多轮对话，所有消息按会话 ID 关联

**异常处理**：AI 超时 30s 或 API 不可用 → 返回"AI服务暂时不可用，请选择人工客服"

**涉及的表**：`chat_session`、`chat_message`

**代码**：`ChatController.java`，`getAIResponse()` 方法调用 DeepSeek API

---

### 2.4 晚归打卡

**打卡规则**：每晚 22:00-23:00 可打卡，23:00 之后算"晚归"

**流程**：
1. 学生点击打卡 → 记录 `check_date` + `check_time`
2. 系统判断是否晚归（23:00 后 → `is_late=1`）
3. 每日只能打一次，重复打卡返回"今日已打卡"
4. 未按时打卡 → 学生提交补卡申请（`check_in_apply` 表）
5. 宿管审批补卡 → 通过后在 `check_in` 表补录一条记录（status=0 补卡）

**涉及的表**：`check_in`、`check_in_apply`、`check_in_setting`

**代码**：`CheckInController.java`

### 2.5 水电费查看与缴费

**计费逻辑**：宿管录入用水用电量 → 系统按宿舍类型读对应的单价（utility_threshold 表）→ 自动计算费用

**流程**：
1. 学生查看本月水电账单（`utility_bill` 表）
2. 查看历史账单（按月筛选）
3. 在线缴费 → 选微信/支付宝 → 弹二维码 → 15 秒后自动标记已支付
4. 已支付的账单 `is_paid=1`

**涉及的表**：`utility_bill`、`utility_threshold`、`room`

**代码**：`UtilityController.java`（水电费）、`UtilityThresholdController.java`（阈值配置）

### 2.6 失物招领

**两种发布类型**：

| type | 含义 | 场景 |
|------|------|------|
| 1 | 失物 | 我丢了东西，发布寻找 |
| 2 | 拾物 | 我捡到东西，发布招领 |

**三种状态**：

| status | 含义 |
|--------|------|
| 0 | 待认领（刚发布） |
| 1 | 已认领（有人认领成功） |

**发布流程**：
1. 学生填写物品名称、分类、丢失/拾取时间、地点、描述、联系方式
2. 可选上传照片（`images` 字段，多图逗号分隔）
3. 提交 → `status=0`，记录 `publisherId`

**查询流程**：
- 所有学生可查看完整列表（分页）
- 支持按类型（type）、物品分类（itemType）、状态（status）、日期范围筛选
- 列表显示发布人姓名和学号（关联 student 表查 `publisherId`）
- 按创建时间倒序，最新发布在最前面

**认领流程**：
- 找到物品 → 调用认领接口 → status 从 0 变为 1
- 认领后不再显示在待认领列表中

**管理员功能**：
- 编辑和删除单条记录
- 按状态批量删除（如一键清除所有已认领的记录）

**涉及的表**：`lost_and_found`

**代码**：`LostAndFoundController.java`
- `add()` 第 40 行 — 发布，status 初始化为 0
- `list()` 第 60 行 — 列表查询，支持 type/itemType/status/日期范围 6 种筛选
- `getItemTypes()` 第 123 行 — 获取已有物品分类列表（去重）
- `update()` 第 149 行 — 编辑记录
- `delete()` 第 162 行 — 删除单条
- `claim()` 第 174 行 — 认领，status 0→1
- `deleteByStatus()` 第 188 行 — 按状态批量删除

**字段**：`itemName`（物品名称）、`itemType`（分类）、`lostTime`（时间）、`lostPlace`（地点）、`description`（描述）、`contact`（联系方式）、`images`（照片）、`publisherId`（发布人ID）、`status`（状态）

## 三、宿管员端功能

### 3.1 学生管理（本楼栋）

**代码**：`StudentController.java`

---

### 3.2 床位分配

**床位状态**：0-空闲、1-占用、2-维修中、3-损坏待修

**流程**：
1. 选择学生 → 选择空闲床位 → 绑定
2. 床位状态变为"占用"，学生表的 room_id、bed_number 更新
3. 宿舍的 current_count +1
4. 支持按班级批量分配

**涉及的表**：`bed`、`student`、`room`

**代码**：`BedController.java`

---

### 3.3 退寝办理

**流程**：
1. 宿管确认退寝 → 录入资产清点结果
2. 释放床位（status=0，studentId=null）
3. 学生表的 room_id、bed_number 清空
4. 宿舍 current_count -1
5. 记录到 `check_out` 表

**涉及的表**：`student`、`bed`、`room`、`check_out`

**代码**：`BedController.java`、`RoomController.java`

---

### 3.4 报修处理

**流程**：
1. 查看本楼栋所有报修单
2. 紧急工单（is_emergency=1）置顶标红
3. 接单（status 0→1）
4. 可选：转派给指定维修师傅（填 repair_person 字段）
5. 维修完成（status→3）→ 自动通知学生评价

**代码**：`RepairController.java`

### 3.5 卫生检查

**流程**：
1. 宿管对宿舍进行卫生打分（1-10 分）
2. 拍照留证 + 填写问题描述
3. 检查结果同步展示到学生端
4. 作为文明宿舍评选的数据基础

**涉及的表**：`health_check`

**代码**：`HealthCheckController.java`

---

### 3.6 水电费管理

**流程**：
1. 宿管录入本楼栋某宿舍当月水电用量
2. 系统根据宿舍类型（4/6人间）读取单价和限额
3. 自动计算费用：用电量×电单价 + 用水量×水单价
4. 检查是否超限 → 超限则创建预警 + 通知学生
5. 支持 Excel 批量导入水电用量
6. 欠费超 5 天发送催缴通知

**涉及的表**：`utility_bill`、`utility_threshold`、`utility_warning`、`message`

**代码**：`UtilityController.java`（账单 + 预警）、`UtilityThresholdController.java`（阈值）

### 3.7 打卡统计与补卡审批

**流程**：
1. 查看本楼栋当日打卡率（已打卡/应打卡）
2. 生成未打卡学生名单

**流程**：

2. 按宿舍分组，计算平均分
3. 按得分降序排列

5. 支持按年份和月份查询历史排名

**涉及的表**：`health_check`、`civilized_dormitory`

## 五、跨模块通用逻辑

### 5.1 权限控制

**实现方式**：数据层面细粒度过滤，不是 URL 拦截

1. `JwtAuthenticationFilter` 解析 Token，把 userId 和 userType 放入请求上下文
2. Controller 里根据 userType 和数据范围过滤：
   - 学生 → 只查自己的数据
   - 宿管 → 只查本楼栋（building_id）的数据
   - 管理员 → 查所有数据

**安全配置**：`SecurityConfig.java` → 放行 `/api/auth/**`，其余需登录

### 5.2 消息通知

系统自动推送消息的场景：
- 报修接单、维修完成 → 通知学生
- 水电超限预警 → 通知该宿舍所有学生
- 换寝审批结果 → 通知申请学生
- 床位分配/退寝 → 通知学生+管理员

消息写入 `message` 表，前端显示时自动区分已读/未读。

**代码**：`MessageController.java`

### 5.3 文件上传

- 统一入口：`UploadController.java`
- 支持类型：图片（报修照片、卫生检查照片、头像）
- 限制：单文件不超过 10MB（application.yml 配置）
- 存储路径：项目 `uploads/` 目录
