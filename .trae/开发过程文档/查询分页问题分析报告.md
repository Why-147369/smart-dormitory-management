# 查询分页限制问题分析报告

## 一、概述

通过对系统代码的分析，发现系统中存在大量全量查询 `selectList(null)` 的情况，这些查询未添加分页限制，在数据量大的情况下会导致严重的性能问题。本报告详细列出各功能模块中存在的分页问题。

---

## 三、高风险问题汇总

以下问题需要优先处理：

| 优先级 | 模块 | 功能 | 问题 |
|--------|------|------|------|
| **高** | 文明宿舍 | 计算得分 | 全量查询卫生检查记录，无日期过滤 |
| **高** | 学生管理 | 床位选择 | 全量查询所有床位 |
| **高** | 打卡管理 | 打卡列表 | 全量查询所有学生 |
| **高** | 换寝申请 | 申请换寝 | 全量查询学生列表 |
| **高** | 访客管理 | 访客预约 | 全量查询学生列表 |
| **高** | 床位管理 | 床位分配 | 全量查询学生和床位 |

---

## 四、优化建议

### 4.1 立即可做（高优先级）

1. **文明宿舍计算**：添加月份过滤条件
2. **学生下拉列表**：添加LIMIT限制，如 `LIMIT 100`

### 4.2 建议优化（中优先级）

1. 所有列表接口添加分页参数
2. 添加最大分页数限制（如最大50条）

### 4.3 可暂不做（低优先级）

1. 配置类数据查询（如报修类型、楼栋下拉框），数据量小，影响有限

---

## 五、修改示例

### 示例1：文明宿舍计算

```java
// 修改前（高风险）
List<HealthCheck> allChecks = healthCheckMapper.selectList(null);

// 修改后
LambdaQueryWrapper<HealthCheck> wrapper = new LambdaQueryWrapper<>();
wrapper.between(HealthCheck::getCheckDate,
    LocalDate.of(year, month, 1),
    LocalDate.of(year, month, 28));  // 或使用当月最后一天
List<HealthCheck> allChecks = healthCheckMapper.selectList(wrapper);
```

### 示例2：学生下拉列表

```java
// 修改前
List<Student> students = studentMapper.selectList(null);

// 修改后 - 限制数量
LambdaQueryWrapper<Student> wrapper = new LambdaQueryWrapper<>();
wrapper.select(Student::getId, Student::getName, Student::getStudentNumber);
wrapper.last("LIMIT 100");
List<Student> students = studentMapper.selectList(wrapper);
```

## 六、总结

- **总计发现问题**：40处全量查询
- **高风险**：6处（需立即优化）
- **中风险**：12处（建议优化）
- **低风险**：22处（可暂不做）

建议优先处理高风险问题，可显著提升系统性能。
