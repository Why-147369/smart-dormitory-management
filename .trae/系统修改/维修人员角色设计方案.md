# 维修人员角色功能 — 设计方案

## 一、现状分析

目前维修人员的处境：**只是数据库里的一条记录，不能登录系统。**

| 现状 | 问题 |
|------|------|
| `maintenance_person` 表只有 name/phone/specialty | 没有账号密码，无法登录 |
| `repair` 表 `repairPerson` 字段是 `varchar` | 存的是维修师傅名字，不是 ID，无法关联 |
| 维修完成时宿管手动选师傅名字 | 师傅本人无法主动接单、无法标记维修进度 |
| 只有 3 种登录角色（1学生 2宿管 3管理员） | 用户类型枚举需要扩展到 4 |

---

## 二、改动总览

```
需要改动的层：
├── 数据库：1 张表加字段
├── 后端：6 个文件改动
└── 前端：新增 6 个页面 + 改 1 个路由
```

## 三、数据库改动

### 3.1 `maintenance_person` 表加字段

```sql
ALTER TABLE maintenance_person 
ADD COLUMN username VARCHAR(50) COMMENT '登录账号',
ADD COLUMN password VARCHAR(100) COMMENT '密码(BCrypt加密)',
ADD COLUMN last_login_time DATETIME COMMENT '最后登录时间';
```

### 3.2 `repair` 表修改

```sql
-- 把 repairPerson 从手填名字改为关联 ID
ALTER TABLE repair 
ADD COLUMN maintenance_id BIGINT COMMENT '维修人员ID',
ADD COLUMN accept_time DATETIME COMMENT '维修人员接单时间';
-- 保留 repairPerson 字段但不再使用，或者直接复用 repairPerson 存 ID
```

> 简化方案：直接复用 `repairPerson` 字段存维修人员的 ID（之前存的是名字字符串，现在改为存 ID），少改一张表。

## 四、后端改动

### 4.1 `AuthServiceImpl.java` — 登录支持维修人员

当前只支持 userType 1/2/3，需增加 userType=4：

```
如果 userType == 4：
    查 maintenance_person 表 WHERE username = ?
    BCrypt 比对密码
    调用 JwtUtil.generateToken(维修人员ID, 4, username)
    记录登录日志
```

### 4.2 `JwtUtil.java` — 无需改动

已经支持 `Integer userType`，传 4 即可。

### 4.3 `MaintenancePersonController.java` — 增加接口

新增 3 个接口：

| 接口 | 功能 |
|------|------|
| `GET /maintenance/me` | 获取当前登录维修人员信息 |
| `GET /maintenance/repairs` | 查看分配给自己的维修工单列表 |
| `PUT /maintenance/repair/accept/{id}` | 接单（status 1→2，记录 accept_time） |

### 4.4 `RepairController.java` — 修改变更

**宿管完成报修时**：不再让宿管手填 `repairPerson`，而是从 `GET /maintenance-person/by-type` 选择维修人员 ID，存到 `repair` 表的 `maintenance_id` 字段。

**维修人员接单时**：`MaintenancePersonController` 的新接口把 status 改为 2（维修中）。

### 4.5 `entity/MaintenancePerson.java` — 加字段

```java
private String username;
private String password;
private LocalDateTime lastLoginTime;
```

### 4.6 `entity/Repair.java` — 加字段

```java
private Long maintenanceId;      // 维修人员ID
private LocalDateTime acceptTime; // 接单时间
```

## 五、前端改动

### 5.1 新增页面（`src/views/maintenance/`）

| 文件 | 功能 |
|------|------|
| `layout/index.vue` | 维修人员端布局（侧边栏 + 顶栏） |
| `dashboard/index.vue` | 首页：今日待处理工单数、已完成统计 |
| `repair/index.vue` | 我的工单列表：待接单/维修中/已完成 |
| `repair/detail.vue` | 工单详情：报修信息、接单、完成操作 |
| `login/index.vue` | 维修人员登录页（共用现有登录页，userType=4） |

> 登录页不需要新建，现有 login 页加一个"维修人员"选项即可。

### 5.2 路由修改（`router/index.js`）

新增：
```js
{
  path: '/maintenance',
  component: () => import('@/views/maintenance/layout/index.vue'),
  meta: { requiresAuth: true, role: 4 },
  children: [
    { path: 'dashboard', component: () => import('@/views/maintenance/dashboard/index.vue') },
    { path: 'repair', component: () => import('@/views/maintenance/repair/index.vue') },
  ]
}
```

### 5.3 现有页面修改

**宿管端报修处理页**：完成报修时，维修人员选择从"手填名字"改为"从 maintenance_person 表下拉选择 ID"。

**登录页 `login/index.vue`**：角色选择加一项"维修人员"。

## 六、维修人员完整业务流程

```
维修人员登录（userType=4）
  ↓
查看"我的工单"列表（GET /maintenance/repairs）
  ↓
看到待接单的工单 → 点击接单（PUT /maintenance/repair/accept/{id}）
  ↓
status → 维修中（2），记录 accept_time
  ↓
维修完成 → 点击完成（PUT /repair/complete/{id}）
  ↓
status → 已完成（3），通知学生评价
```

## 八、风险评估

| 风险 | 应对 |
|------|------|
| `repairPerson` 字段从名字改为存 ID，历史数据不兼容 | 先 `ALTER TABLE` 加 `maintenance_id`，新旧字段并存，前端优先用新字段 |
| 维修人员登录后权限控制 | SecurityConfig 不用改，数据层过滤即可：维修人员只能看分配给自己的工单 |
| 现有宿管端字段改动影响已有功能 | 宿管端选择维修人员改为"下拉选择 ID"，后端兼容旧的手填方式 |
